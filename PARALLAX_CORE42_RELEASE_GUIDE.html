Parallax Core 42

42 named, deterministic measurements of an H&E patch. Built to find the batch you didn’t know you had.

Core42 turns an RGB histology patch into 42 numbers, each a named formula: soft-gradient fields, haematoxylin-channel blob statistics, the geometry of luminance and colour-opponent edges, multiscale void and orientation structure, and radial organisation. No training, no reference cohort at run time, no randomness: the same pixels give the same numbers.

That makes it sensitive to the tissue and to everything that happened to it: the site, the scanner and file conversion, the stain, the sampled extent. In a cohort, that sensitivity is useful. If your slides split by how they were made, Core42 tends to show it, and it shows which named measurements do the splitting, so you can go and look.

  • Provenance and cohort QC. Do your slides group by site, scanner, production route or preparation? Which axes separate them? Worked example on TCGA-COAD.
  • An interpretable block next to colour. In a pre-registered Camelyon17 test, adding the 42 axes to colour summaries raised AUROC by +0.044 to +0.046, including with whole hospitals held out (+0.046).
  • Section fingerprints. Two non-overlapping tile sets from the same TCGA slide find each other 89% of the time (top-1 nearest-neighbour retrieval over quantile summaries, 174 slides).

It is not a better classifier than ordinary texture features. In both pre-registered tests a plain grayscale-texture family scored higher than the 42 axes on their own, and on held-out hospitals higher than colour plus the 42 axes. It is not a per-slide artefact detector either: for blur, folds and pen marks use HistoQC. Read How it compares before citing a number.

Install

pip install "parallax-core42 @ git+https://github.com/parallaxmetrology/parallax-core42"

Python 3.11+, numpy, scipy, scikit-image, Pillow. A validated wheel is in dist/.

Use

parallax-core42 patch.png --output measurements.csv
parallax-core42 patches/ --recursive --output measurements.jsonl

# optional, explicit: corrected fixed-Macenko normalisation with the bundled target
parallax-core42 patches/ --recursive \
  --macenko-target references/tcga_fixed_macenko_target.json --output normalised.csv
from parallax_core42 import AXES, measure_path

row = measure_path("patch.png")
assert row["status"] == "ok"
values = [row[axis] for axis in AXES]   # 42 floats in frozen order

Each output row has 14 provenance and status fields followed by the 42 axes. Long edges above 512 px are reduced to 512; smaller patches are not enlarged. The constants are frozen: a modified configuration raises an error, and any change would be a new, separately named schema.

Worked example: TCGA production routes

181 TCGA-COAD patients, 8 tumour tiles each, from three production routes: regular site-AA scans, 15 small derivative files from the same site, and Aperio scans from five other sites. Image only, plan hashed before measuring.

  • No labels: the derivative slides sit apart from everyone else on the first two principal components.
  • No fitting, per axis: 19 of 42 axes separate derivative from regular AA patients at AUC ≥ 0.8 or ≤ 0.2, led by the pixel-scale axes (gap_ds, k_ds 1.00). Those slides’ tiles were enlarged about 2.5×, and the axes defined in pixel distances are the ones that notice.
  • Named fitted readout: shrinkage LDA, leave one patient out, separates all three routes with balanced accuracy 0.977 (0.960 after normalisation).

Groups already known to differ, so a demonstration rather than a discovery. The point is the named axes that carry each split. Details, caveats and a script to run the same report on your own cohort: examples/tcga_route_fingerprint, examples/fingerprint_cohort.py.

What to know before using it

  • Frame- and scale-dependent by design. Several axes change with rotation or crop, and all act in pixels, not microns. Control patch size and resolution, or study them. Core42 never infers µm/px.
  • Some names overstate. blob_density is a detection rate, not a nucleus count; omega is mask-centroid disagreement, not the reference-based “Omega” of earlier Parallax documents.
  • Normalisation is optional and changes several axes. The bundled normaliser is the corrected one; the degenerate version from early Parallax work is excluded. Normalising does not remove site structure.
  • A grouping is a lead, not a cause. Core42 records handling as well as biology.

Full list: docs/KNOWN_ISSUES.md. Every axis, its unit and its caution: docs/AXIS_DICTIONARY.md and .csv. What it does not claim: docs/SCOPE_AND_BOUNDARIES.md.

Validate

pip install -e ".[dev]"
PYTHONPATH=src python validate_release.py --check-only    # 71 checks
shasum -a 256 -c MANIFEST_SHA256.txt
pytest -q

On its reference platform (macOS arm64, locked versions in requirements-lock.txt) the release reproduces the archived v4.1 research kernel on all 42 axes with maximum absolute difference 0.0, on a bundled synthetic fixture and on a real H&E tile (not bundled). Other platforms differ at the floating-point level (up to about 1.4e-8 relative on Linux x86_64); CI checks both, and scripts/platform_check.py reports the differences on your machine. The fixture is synthetic and redistributable; it exercises the numerical path and says nothing about biology. Details: docs/VALIDATION.md, docs/PROVENANCE.md.

Contribute

  • Run it on your cohort and report what grouped and what didn’t, using the “Results on your cohort” issue template. A null is as useful as a hit.
  • Bring a cohort with known batches (restains, rescans, scanner changes): that is the test this instrument most needs.
  • Spot an axis whose description doesn’t match how a pathologist or imaging scientist would read it.

Scope and claim boundaries

What Core 42 is

Core 42 is a fixed deterministic mapping from an RGB image patch to 42 scalar measurements. The mapping contains no fitted model, class label, reference cohort, outcome, random sampling, or patient information.

The word “deterministic” means that the same decoded pixels, configuration, software environment, and numerical platform should produce the same output within the recorded tolerance. It does not mean that different crops, scanners, compression levels, stains, orientations, or library versions are guaranteed to agree.

What it is not

Core 42 is not:

  • a classifier;
  • a training-free diagnostic system;
  • a survival biomarker;
  • a stain-invariant representation;
  • a rotation-, translation-, or crop-invariant representation;
  • a cell segmentation or nucleus-counting system;
  • a whole-slide sampler;
  • an implementation of structural address compartments;
  • a patient or specimen identification product;
  • a medical device.

Downstream supervised readouts, reference distances, spatial compartments, and whole-slide aggregation are distinct analytical layers. They must be trained or defined only within the appropriate training data and evaluated with grouped, patient-separated, and site-aware designs when the task requires them.

Relationship to the evidence programme

The 42-axis panel is the frozen common measurement block used across the verified section-persistence line and later external assays. Other programme results used additional or differently summarized measurements:

  • the historical “58-axis” language referred to a broader notebook-era frame;
  • EBHI and STHELAR structural-address experiments used study-specific 45-summary compartment representations;
  • raw-color, grayscale, and simple-edge controls are separate representations;
  • reference-dependent deviation scores and fitted LDA models are separate layers.

This release therefore anchors one stable measurement object. It does not claim to be a single executable reproduction of every historical analysis.

Required reporting

Every study using Core 42 should report:

  1. package version and manifest hash;
  2. input patch dimensions and physical resolution, if known;
  3. crop and tissue-selection procedure;
  4. raw versus normalized input status and normalizer target hash;
  5. image orientation or augmentation policy;
  6. aggregation, scaling, imputation, and fitted readout;
  7. patient, slide, site, and batch separation rules;
  8. failed measurements and non-finite-value handling.

The v1.0 constants are locked in executable code. A parameter change is a derivative instrument and must receive a new schema identifier, axis dictionary, and validation record.

Parallax Core 42 axis dictionary

The machine-readable authority is AXIS_DICTIONARY.csv. The 42 columns are emitted in the frozen order defined by parallax_core42.schema.AXES.

Two meanings historically called Omega

The omega column in Core 42 is the mean pairwise distance among centroids of eligible mask fields. It is a patch measurement and requires no reference cohort.

Some historical Parallax documents also used “Omega” for a separate, reference-dependent distance from class or cohort norms. That quantity is not part of Core 42. A future reference layer may calculate it from selected Core 42 axes, but it must use a separately versioned reference file and a distinct output name.

Units and scale

Most outputs are dimensionless operational indices. Pixel-valued blob sizes and fixed Gaussian scales only have comparable physical meaning when input resolution is controlled. The extractor records image dimensions and its resize ceiling, but it does not infer micrometres per pixel. Whole-slide sampling and physical-scale harmonization belong to the study protocol.

Orientation and crop dependence

Several axes are deliberately frame-relative. Peripheral mass, centroid paths, orientation coherence, and some composites can change with rotation, reflection, translation, or crop choice. Core 42 is deterministic; it is not geometrically invariant. Such transformations should be prespecified controls when relevant.

Preprocessing and physical scale

Core image handling

The extractor converts files to RGB and reduces the longest image edge to the configured ceiling, 512 pixels by default, using Pillow Lanczos resampling. It does not enlarge smaller images. Non-square images retain their aspect ratio.

In Core 42 v1.0 the 512-pixel ceiling and all measurement constants are frozen, not user-tunable command-line settings. A changed constant requires a new schema.

Core 42 does not select tissue, reject background, sample a whole slide, or infer micrometres per pixel. Those operations determine what the patch represents and must be frozen in the study protocol.

Physical resolution

Several measurements use fixed pixel scales. Blob radii use sigma 6–20 pixels; multiscale orientation uses sigmas 1, 8, and 32 pixels; adaptive morphology and minimum-object thresholds also act in pixel units. Comparisons across datasets are physically interpretable only when patch resolution and field of view are controlled or explicitly studied.

For the recent persistence experiments, the dominant standardized arm measured 512×512-pixel fields at 0.50 micrometres per pixel. That study convention is not hard-coded into Core 42.

Stain normalization

The optional FixedMacenkoNormalizer is the corrected mean-centred covariance implementation used in the recent verification programme. The historical uncentred-SVD implementation was mathematically degenerate and is not included.

Normalization is intentionally a separate step because:

  • it changes several measurement axes;
  • it requires an explicit target;
  • it does not remove all site, scanner, preparation, composition, or extent signal;
  • raw and normalized measurements can answer different audit questions.

The bundled target records the matrix and concentration values used in the recent TCGA-derived path. It is included for reproducibility, not promoted as a universal reference. A new study may fit another target, but must preserve that target and must not compare results as if the references were interchangeable.

Recommended paired assay

When technical sensitivity is part of the question, retain parallel arms:

  1. raw RGB input;
  2. explicitly normalized input;
  3. simple grayscale or edge controls;
  4. recorded crop, physical scale, scanner, site, preparation, and slide extent.

This makes technical and structural channels inspectable rather than assuming that normalization has erased them.

Provenance and reconstruction record

Frozen source

The numerical source for Core 42 is the archived v4.1 kernel:

  • historical filename: parallax_pathology_v41.py
  • historical SHA-256: b6fc19229b98f854c95bfcb1c3ebb8040cd935303ec1be0cbf1349d14d30a43e
  • reconstructed release: parallax-core42 version 1.0.0
  • reconstruction date: 3 September 2026

The 42-axis order is the frozen STRUCTURAL_AXES list used by the verified Degas, TCGA cross-slide, TCGA same-portion, HER2-ST, HTAN, CAMELYON, and CPTAC analyses.

What was retained

The release retains the numerical definitions required to calculate the 42 axes:

  • sRGB linearization, LAB-L and cone transforms;
  • fixed H&E deconvolution matrix;
  • gradient and opponent masks;
  • kernel, relational, multiscale, blob, composite, and radial calculations;
  • the 512-pixel default resize ceiling and v4.1 constants.

What was removed

The release excludes material not required by the 42-axis measurement contract:

  • Colab and notebook state;
  • machine-specific paths;
  • TCGA zip discovery and patient sampling;
  • class labels and outcome data;
  • GLCM and tonal outputs outside the frozen 42-axis panel;
  • the ambiguous reference-dependent Omega engine;
  • fitted classifiers, cohort scaling, retrieval, and survival analysis;
  • the historical degenerate Macenko implementation.

Optional corrected Macenko normalization is provided as a separate module. Its bundled target is copied numerically from stage2_normalizer.json, source SHA-256 d2f71ff6bb3d02f86f3d2700a394a1a28fb89adb907258afb1f3b30de2b983ef. The clean normalizer was also compared against LOCAL_PIPELINE/run_batch.py, source SHA-256 566bdb05ae2bf92d52d450d3bd0eab64e42784554066859d903e713c6bc4d6ff. On the frozen fixture, all 786,432 RGB channel values were identical.

Compatibility edits

Deprecated scikit-image aliases were replaced with their current equivalents. The new max_size threshold was chosen to reproduce the historical strict “remove objects smaller than minimum size” behavior. Region-property aliases were updated without changing the calculation.

Numerical adjudication

scripts/verify_against_historical_source.py loaded the archived source independently and compared all 42 outputs on both the frozen synthetic fixture and a real TCGA H&E tile already held in the verification archive. Both comparisons produced 42 of 42 axes matching at relative and absolute tolerance 1e-12, with maximum absolute difference 0.0. The real tile is not duplicated in this software packet; its SHA-256 is preserved in the validation record. The historical source is not required after installation; the self-contained synthetic known-answer fixture guards subsequent runs.

This proves implementation equivalence for the tested input and environment. It does not prove equivalence on every possible image, biological validity, external performance, or stability under future dependency versions.

Validation protocol

Run from the release root:

PYTHONPATH=src python validate_release.py --check-only
shasum -a 256 -c MANIFEST_SHA256.txt

Omit --check-only only when intentionally regenerating the deterministic validation/RELEASE_VALIDATION.json record before rebuilding the manifest.

The validator checks:

  • exactly 42 unique axes and frozen family order;
  • exact output-column order;
  • frozen fixture SHA-256;
  • every raw known-answer axis within the numerical tolerance;
  • axis dictionary identity and completeness;
  • 42-of-42 equivalence against the archived v4.1 source on both the bundled synthetic fixture and a non-bundled real H&E verification tile;
  • the pinned optional normalization target;
  • pixel-identical optional normalization against its archived implementation;
  • absence of machine-specific paths, class labels, and reference-dependent Omega logic from executable package code;
  • unit, deterministic-repeat, normalized known-answer, and CLI tests.
  • wheel construction, isolated-target installation, and byte-identical CLI output.

The synthetic fixture is not histology and cannot validate biological meaning. It is deliberately redistributable and exists only to exercise the numerical path.

The direct dependency versions are recorded in requirements-lock.txt; interpreter and platform details are in validation/BUILD_ENVIRONMENT.json. Broader versions admitted by pyproject.toml are convenience ranges, not evidence of exact cross-version numerical identity. Rebuild the known-answer validation whenever the environment changes.
